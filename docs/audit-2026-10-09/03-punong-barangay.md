# Audit 03 - Punong Barangay (executive / approver) web experience

Date: 2026-10-09. Scope: dashboard, gis, analytics (Reports + Heatmap), approvals, accomplishment-reports, referrals, school-zones (read), personnel (scheduler publish), settings, incident-detail (read-only). Method: static reading of `web/src`, `web/css`, `backend/controllers`, plus `node web/scripts/verify-web-wiring.mjs` (779 passed, 0 failed). No browser, no device and no real DB was used. Nothing outside this file was modified.

Severity: P0 unsafe or legally exposing, P1 wrong or misleading, P2 friction, P3 polish. Effort: S/M/L.

## What is solid

- The dashboard KPI definition text is correct and matches the SQL (`admin-dashboard.js:643` vs `ReportsController.php:189-200`). Per-incident `MIN(arrived_at)` is used for the average, the per-day series (`:218-241`) and the export (`:754-780`), so screen and file agree. `null`, not 0, is returned when there are no arrivals (`:207`, `:246`) and `LineChart` renders `null` as a gap (`LineChart.js:22-30,151-166,306`).
- Date handling is Asia/Manila with UTC bounds and a 366-day cap (`ReportsController.php:344-358`); the shared `DateRangePicker` handles the popover on narrow screens.
- Raw narrative is withheld from PB server-side (`IncidentsController.php:624-632`) and the UI says so (`incident-detail.js:363-365`). Accomplishment entry text is withheld unless the viewer holds a note/approve authority (`AccomplishmentController.php:379-381`) and the UI explains it (`accomplishment-reports.js:368-370`). Evidence files are not reachable by PB on the server (`IncidentsController.php:664`).
- Each irreversible approval has a confirm step with inline error that keeps the dialog open (`accomplishment-reports.js:475-491`). The preparer-cannot-approve rule is explained in plain language on 409 (`tanodWorkflowUi.js:211-218`), and Annex D explains it up front (`school-zones.js:913-921`).
- Approvals has per-group loading/empty/error states, hides groups the viewer cannot act on, and explains "no authority" (`approvals.js:212-219`). The dashboard widget has all four states (`admin-dashboard.js:424-482`).
- The referral log is a true delegation log with no names or narrative (`referral-log.js:6-15`).
- `verify-web-wiring.mjs`: 779 passed, 0 failed.

# Audit 04 — Personnel, roster, approvals and paper workflows (web)

Date: 2026-10-09. Read-only audit. Lens: people-and-paperwork on the web (Personnel hub: Users / Scheduler / Swap requests, Approvals, Accomplishment Reports, paper approval panel and scans, Annex D approvals), compared with the backend controllers.

Method: read `docs/REFERENCE.md`, `docs/WORKFLOWS_AND_RULES.md` (state machines 3-5, rules 26-36 and 62-65, scenarios 8-10), then the web pages and the matching PHP controllers. `node web/scripts/verify-web-wiring.mjs` was run: 779 passed, 0 failed (it cannot catch the defects below). Nothing was run in a browser. All paths are relative to the repo root; `web/src/pages` is shortened to `pages/` below.

Severity: P0 unsafe or legally exposing, P1 wrong or misleading, P2 friction, P3 polish. Effort: S under half a day, M a day or two, L more.

## What is solid

- The approval-authority model is enforced properly server-side: authorities are a separate set, only admin/secretary/punong_barangay can hold them, an Admin cannot change their own approve_* (`UsersController.php:603-614`), the preparer cannot note or approve (`ApprovalAuthority::assertNotPreparer`, `AccomplishmentController.php:506-508`), and paper signers are validated active, same-barangay and authorised (`PaperApproval::requireSigner`).
- The UI mirrors these gates without adding actions the server forbids: Note/Approve/Return hide for the preparer and non-holders (`accomplishment-reports.js:391-396`), and each "why no buttons" message is plain language (`:466-473`). The preparer-must-differ 409 is translated into a plain sentence (`tanodWorkflowUi.js:211-218`). Annex D follows the same pattern (`school-zones.js:869-873`).
- Draft/Published is shown on every shift row, and the swap re-approval state has its own label (`scheduler.js:677-698`). Draft shifts are explained in the form note and the publish bar (`:502-507,1072-1074`). Paper-approved shifts show "Approved on paper <date> (recorded by ...)".
- Paper flow exists end to end for reports and Annex D: "Paper signature pending" badge, record date (correctable), record approval from paper with signer/date, scan upload with type/size checks and an authenticated download (`PaperApprovalPanel.js`); server-side magic-byte checks, rate limit, no stored path returned, audited.
- Four UI states (loading, empty, error with retry, populated) are implemented on the availability panel, scheduler, approvals groups, swap and reports pages; each Approvals group fails independently.
- 404 for draft swap requests and cross-tenant objects; publish is idempotent (replay audit); roster writes are serialised per tanod for the 12 h/day cap; optimistic version checks on shift and swap updates.
- The printed accomplishment report mirrors the barangay's own form (31 day rows, Prepared/Noted/Approved By) and escapes server text (`accomplishment-reports.js:501-554`).
- `verify-web-wiring.mjs`: 779 passed, 0 failed.

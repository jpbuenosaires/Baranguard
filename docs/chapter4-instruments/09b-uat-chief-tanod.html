Introduction Panimula

Baranguard is a system that helps the barangay tanods and officials of Dao, Binanuahan, Marifosque and Banuyo, Pilar, Sorsogon. It sends tanods to incidents, shows where they are, sends SOS alerts, and lets tanods write reports even with no signal. It works beside the DILG BIMSS and does not replace it. This form is part of a capstone study at Bicol University (IT 124).

Ang Baranguard ay sistemang tumutulong sa mga tanod at opisyal ng apat na barangay sa Pilar, Sorsogon. Nagpapadala ito ng tanod sa insidente, nagpapakita kung nasaan sila, at nagpapadala ng SOS. Maaari ring sumulat ng ulat ang tanod kahit walang signal. Bahagi ito ng pag-aaral sa Bicol University.

Purpose of this form. To check, for your job, that Baranguard does what the barangay needs. Each task is short and has a result that should happen. You do the task and mark Pass or Fail. The facilitator watches, times the task and logs any defect.
Who does it. The real Chief Tanod (Admin), who does the tasks in Part B. A member of the development team may not be the tester. The test uses pretend data only.
Layunin ng form na ito. Suriin, para sa inyong trabaho, kung ginagawa ng Baranguard ang kailangan ng barangay. Maikli ang bawat gawain at may resultang dapat mangyari. Gagawin ninyo ang gawain at kayo ang magmamarka ng Pass o Fail. Manonood, maglalagay ng oras at magtatala ng anumang defect ang facilitator. Sino ang gagawa. Ang tunay na Tanod, Chief Tanod (Admin), Secretary o Punong Barangay, na bawat isa ay gagawa lamang ng mga gawain para sa sarili niyang tungkulin (Bahagi B). Hindi maaaring maging tester ang miyembro ng development team. Peke lamang ang datos na gagamitin.

Ground rules Mga patakaran

  1. The tester does every step personally. The facilitator only watches and writes. The facilitator does not touch the phone or keyboard.
    Ang tester mismo ang gumagawa ng bawat hakbang. Nanonood at nagsusulat lang ang facilitator. Hindi hinahawakan ng facilitator ang telepono o keyboard.
  2. Only pretend data is used. No real personal data is typed.
    Peke lamang na datos ang gagamitin. Walang totoong personal na datos na tinatype.
  3. The tester marks Pass only when the result on the screen matches “What should happen”. If not, the tester marks Fail and says what happened; the facilitator writes it in Remarks and gives a Defect ID. The facilitator never changes the tester's mark; if the facilitator saw something different, it is written in Remarks.
    Mamarkahan ng tester ang Pass lamang kapag tugma ang resulta sa screen sa “What should happen”. Kung hindi, mamarkahan ng tester ang Fail at sasabihin kung ano ang nangyari; isusulat ito ng facilitator sa Remarks at bibigyan ng Defect ID. Hindi kailanman binabago ng facilitator ang marka ng tester; kung may nakita siyang kakaiba, isusulat ito sa Remarks.
  4. If a task was not tried, leave both boxes empty and write why. If a task depends on a failed one, mark it Fail and write “blocked”.
    Kung hindi nasubukan ang isang gawain, iwang blangko ang dalawang kahon at isulat kung bakit. Kung nakadepende ang gawain sa isang bumagsak, markahan ito ng Fail at isulat ang “blocked”.
  5. The facilitator starts a stopwatch at the start of each task and writes the seconds. Each time the tester makes an error or asks for help, add 1 to Errors or help.
    Magsisimula ang facilitator ng stopwatch sa simula ng bawat gawain at isusulat ang mga segundo. Sa bawat pagkakamali ng tester o paghingi ng tulong, dagdagan ng 1 ang Errors or help.
  6. Do the core tasks first (shaded). Do the optional tasks if there is time.
    Gawin muna ang mga core task (may lilim). Gawin ang mga optional na gawain kung may oras.
  7. Test accounts and passwords are given separately and are never written on this form.
    Hiwalay na ibinibigay ang mga test account at password at hindi kailanman isinusulat sa form na ito.

Ang tester mismo ang gagawa ng bawat hakbang at siya ang magmamarka ng Pass o Fail. Manonood, magsusulat at maglalagay ng oras lang ang facilitator. Peke lang ang datos. Una ang mga core task (may lilim).

How to Mark the Tasks Paano Markahan ang mga Gawain

  • Pass: the screen shows what should happen. The tester ticks the Pass circle.
    Pass: ipinapakita ng screen ang dapat mangyari. Lalagyan ng tsek ng tester ang bilog ng Pass.
  • Fail: the result is different, the step cannot be done, or an error shows. The tester ticks the Fail circle; the facilitator writes what happened in Remarks and gives a Defect ID (also written in the defect log).
    Fail: iba ang resulta, hindi magawa ang hakbang, o may error na lumabas. Lalagyan ng tsek ng tester ang bilog ng Fail; isusulat ng facilitator sa Remarks ang nangyari at bibigyan ng Defect ID (isusulat din sa defect log).
